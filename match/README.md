# ラブカ対戦シミュレーター（match/）

ラブライブ！シリーズ オフィシャルカードゲームのデッキ同士を、実際のレシピで何試合も戦わせるシミュレーターです。
トップの `index.html`（CatChu!アグロシミュレーター）とは別のページです。

## 画面
- **対戦**：自分のデッキ vs 環境デッキ、または総当たり。タイプごとに保存した構築を選べます。
- **ひとり回し**：毎ターン何点出せるかを、デッキファイルに書いた点数の目安と比べます。
- **デッキとカード**：デッキの保存・呼び出し、デッキの決まりの確認、カード効果の組み込み状況。

## フォルダ
| フォルダ | 中身 |
|---|---|
| `engine/` | ルール本体（総合ルール ver.1.06）。`game.js` が1試合の進行、`ai.js` が標準のプレイ方針、`hearts.js` がハート判定 |
| `cards/` | カード効果。全デッキで共有する。`common.js` は効果の文章で登録（同じ文章のカードは全部これで動く）、グループごとのファイル（`liella.js` など）はカード番号で登録。どちらにも無いカードは数値だけで動く |
| `decks/` | 組み込みの環境デッキ。1デッキ1ファイルで、レシピ・回し方の目安（plan）・プレイ方針の上書き（strategy）を持つ |
| `store/` | 保存デッキの窓口。今は LocalStorage。DBに移すときは同じ形のクラスを作って差し替える |
| `data/` | カードデータ（`rabuka_cards.json` をそのまま使う）、前回取り込んだカード番号（`known-ids.json`）、ポイント制限 |
| `tools/` | 新弾レポート（`report.mjs`）、旧CatChu!シミュレーターとの比較（`compare-old.mjs`）、ひとり回し（`solo.mjs`）、1デッキと全デッキの対戦（`vs.mjs`）、総当たり（`matrix.mjs`） |
| `test/` | 動作確認（`node match/test/smoke.mjs`） |

## 複数のコアで回す
試合は1試合ずつ独立していて、乱数の種と先攻・後攻は「何試合目か」で決まるので、試合を分けて別々のコアで回しても、1つで回したときと全く同じ結果になります。

- **画面**：対戦・ひとり回しは Web Worker（`engine/sim-worker.js`・`engine/pool-browser.js`）で回します。使うワーカーの数は「コア数−1」（最低1）。ワーカーが使えないとき（`file://` で開いたときなど）は画面のスレッドで回します
- **ツール**：`tools/vs.mjs`・`tools/matrix.mjs` は worker_threads（`engine/sim-worker-node.js`・`engine/pool-node.js`）で回します。使うコアの数は既定で「コア数−1」、環境変数 `SIM_THREADS` で指定できます
  - `node match/tools/vs.mjs liella-tomakanote 400`：1つのデッキとほかの全デッキ（1組400試合）。3つ目の引数に入れ替え案のモジュール（`export default deck => deck`）を渡せます
  - `node match/tools/matrix.mjs 400 out.json`：総当たり
- 相手の点数の見込み（ひとり回し120回）は一度だけ調べて、各ワーカーに配ります（`profA`・`profB`）
- 仕事の形とまとめ方は `engine/jobs.js`

## カードデータの更新（新弾のとき）
1. 新しい `rabuka_cards.json` で `data/rabuka_cards.json` を置き換える（変換は不要）
2. `node match/tools/report.mjs` で、新カードと効果の対応状況を確認する
   - 既存カードと同じ文章の効果は自動で動く（「対応済み（文章）」）
   - 「未実装」の効果を `cards/` に書く。よく出る文章は `common.js` に文章で、そのカードだけの効果はグループのファイルに番号で
3. 確認が済んだら `node match/tools/report.mjs --update` で `known-ids.json` を更新する
4. `node match/test/smoke.mjs` で動作確認

画面の「デッキとカード」の下にも、同じ状況（新カード・対応状況）が出ます。

## デッキを足すとき
1. `decks/` にファイルを1つ作る（既存のファイルをまねる）
2. `decks/index.js` に1行足す
3. 足りないカード効果を `cards/` に書く

## 回し方の書き方（decks/*.js の strategy）
noteの回し方をデッキファイルに書き写すための項目です。全部書かなくても、標準のAIが動きます。

| 項目 | 中身 | 例 |
|---|---|---|
| `mulliganOpt.keep` | マリガンで残すカードの優先リスト（番号・コスト・枚数。`group` で「どちらか1枚」、`ifKept` で上のルールで残せたときだけ、`ifGroups` で書いたグループがそろったときだけ） | `[{ ids: ['PL!-bp6-019'], n: 1 }, { cost: 4, n: 1 }]` |
| `turnPlan` | ターンごとの目標の盤面（コストか `{ id, cost, area }`）と、置きたいライブの組み合わせ | `{ 4: { board: [[13, 13, 2]], lives: [[GN, MW]] } }` |
| `script` | そのターンに最初に出すカード（番号かコスト、エリア、バトンタッチ元）。出せなければ飛ばす | `{ 3: [{ play: { id: '…' }, area: 1 }] }` |
| `lock` | 指定のターンの間、バトンタッチしないメンバー | `[{ id: '…', area: 1, fromTurn: 3, toTurn: 4 }]` |
| `prefer.wantMembersFrom` | このターンより前は、メンバー回収で `wantMembers` を拾わない | `4` |
| `prefer.fillDistinct` | ライブ置き場の空き枠に伏せるメンバーは、控え室・ステージにまだ無い名前（このグループ）を先に | `'Liella!'` |
| `prefer.toWaiting` | 控え室に送っておきたいカード（踏み倒し・入れ替えの対象）。マリガンで残し、1Tから送る | `['PL!HS-bp6-007']` |
| `prefer.mill` | 山札を削りたいデッキ | `true` |
| `prefer.fillPrefer` | ライブ置き場の空き枠に優先して伏せる（控え室に置いておきたい）カード | 非ブレ虹ヶ咲の15エマ・17彼方など |
| `prefer.protFill` | `false` で、空き枠を埋めるための2コストを手札に抱えない（サーチで手札を捨てやすくする） | `false` |
| `prefer.hold` | 後のターンに必ず使うカードを1枚手札に残す（from〜to のターン。控え室に代わりがあれば残さない。配列で複数書ける） | `{ from: 2, to: 5, ids: [KASUMI], cost: 2, skipIfWaiting: [KASUMI] }` |
| `prefer.wantMembers` | 2コスト（メンバー回収）で優先して拾うメンバー（手札・ステージに無く、控え室にあれば拾う） | `[SHIORIKO9, KANATA9]` |
| `prefer.wantLives` | 2コストなどでライブを拾うとき優先するライブ（手札に無ければ、ほかのライブがあっても拾う） | `[JB]` |
| `prefer.unit` / `prefer.bigLive` | 優先するユニット、2Tから1枚残す大きいライブの点数 | `{ unit: 'CatChu!', bigLive: 6 }` |
| `liveOpt.minScore` | そのターン以降、この点数に届かないライブの組み合わせは置かない（しゃがむ） | `{ 4: 8 }` |
| `liveOpt.pace` | ライブの点数の進行（成功の回数ごとの目標点） | `[1, 4, 7]` |
| `liveOpt.planMinP` | ターンの目標のライブの組み合わせは、成功の見込みがこの値以上なら置く（minP より低くしたいとき） | `0.35` |
| `script` の `oneOf` | 書いた順に試して、最初にできた手順だけ行う（例：9にこがいれば9にこ、いなければほかの9） | `{ oneOf: [{ play: { id: NIKO9 }, onto: { cost: 2 } }, { play: { cost: 9 }, onto: { cost: 2 } }] }` |
| `script` の `ifStage` / `ifWaiting` | ステージ／控え室にこのカードがあるときだけ、その手順を行う（`oneOf` の中の1つにも書ける） | `{ ifStage: { minCost: 13 }, play: { cost: 9 }, onto: { cost: 2 } }` |
| `script` の `only` | その手順でカードを出せたターンは、ほかのカードを出さない（出せなかったときはいつもどおりAIが決める） | `{ play: { cost: 4 }, area: 0, only: true }` |
| `script` の `ifHand` | 書いたカードが全部手札にあるときだけ、その手順を行う | `{ ifHand: [{ id: '4彼方' }, { id: '4花帆' }], play: { id: '4花帆' } }` |
| `script` の `ifStartEmpty` / `ifStartEmptyLt` | そのターンの手順を始めたときのステージの空き枠が n 以上／n 未満のときだけ、その手順を行う | `{ ifStartEmpty: 2, play: { cost: 2 } }`（1Tに1人しか出せなかったら2コストを2枚） |
| 手順のカードの指定 | `id`（1種類）／`ids`（どれか）／`minCost`（このコスト以上）／`cost`（ちょうど） | `{ play: { ids: CERES15 }, onto: { cost: 13 } }` |
| 手順の `unlock` / `ontoWait` | `lock` を無視してバトンタッチする／バトンタッチ元がウェイト状態（起動能力を使ったあと）のときだけ行う | `{ play: { cost: 13 }, onto: { id: YOSHIKO13 }, unlock: true, ontoWait: true }` |
| 手順・目標の条件 `ifSuccess` / `ifNoSuccess` / `ifNoStage` | 成功ライブ置き場にこのカードがある／無い、ステージにこのメンバーがいないときだけ | `{ ifNoStage: { id: MAKI17 }, ifSuccess: MS, play: { id: MAKI17 }, onto: { cost: 9 } }` |
| `turnPlan[n].alt` | 条件に合うときは、そのターンの盤面・ライブの目標を差し替える（条件：ifSuccess・ifNoSuccess・ifStage・ifNoStage・ifHand） | `alt: [{ ifNoSuccess: MS, board: [[9, 2]], lives: [[MS]] }]` |
| `prefer.noRecoverTurns` | このターンは2コスのライブ回収（自分を控え室に置く）を使わない | `[4]` |
| `liveOpt.digFor` | 探すカードがそのターンに手札に無ければ、ライブカード置き場を n 枚まで埋めて引き直す（`keep` のカードは置かない。次のターンの盤面に要るカードも残す。配列で複数書ける。`skipIfStage` でステージにいれば探さない） | `{ ids: [EMMA15], turns: [1, 2], n: 3, keep: [JB] }` |
| `liveOpt.statMin` | 盤面スタッツ（ステージのハートとブレードの合計）がこの値より少ないターンはライブをしない（温存） | `{ 3: 15 }` |
| `liveOpt.bladeMargin` | エールでブレードハートの無いカードがこの枚数めくれても成功する見込みで選ぶ（エールの枚数から引いて計算） | `{ 5: 6 }` |
| `liveOpt.dummyTurns` / `dummyMinLives` | わざと成功しないライブ：そのターンにライブを置かないとき、一番いらないライブを1枚置いてエールをする（控え室を増やす）。手札のライブがこの枚数以上のときだけ | `[2]` / `2` |
| `liveOpt.onlyCombos` | 決まったターン・組み合わせでしか置かないライブ | MIRACLE WAVE を 4T は Guilty Night と |
| `liveOpt.fill` / `fillMaxCost` | ライブ置き場の空き枠に不要なメンバーを伏せて引き直す | `true` / `4` |
| `mainOpt.unitBonus` | ユニットの名前の種類をそろえる | `{ unit: 'CatChu!', w: 0.8 }` |

## AIの判断
- メインフェイズ：出せる組み合わせを全部試し、「手札のライブの成功の見込み × 点数」「ターンの目標の盤面との近さ」などで選ぶ。1枚出すごとに組み直す
- ライブ：対戦では、相手のデッキの点数の見込み（相手のひとり回しから作る）と比べ、「自分がライブに勝つ確率 − 相手がライブに勝つ確率」が一番高い置き方を選ぶ。どう置いても得にならなければ置かない。後攻は先攻が伏せた枚数も見る
- ひとり回しでは、点数の見込みと目標の進行で選ぶ
- 起動能力：メインフェイズの最初・1枚出すごと・最後（ctx.late）に、効果側の `ai` が使うと答えたものを使う
- エネルギーが戻る効果：効果側の `refund`（登場時）・`batonRefund`（バトンタッチで控え室に置かれる側）・`energyPotential`（起動能力で起こせる数）を、出す組み合わせを選ぶときに見込む
- 成功の見込み：効果でデッキの上に置いたカードは必ずめくれる、下に置いたカードはめくれないとして数える。起動能力でまだ足せるブレードは効果側の `estBlades` で見込む

## 仮想の相手（noteの点数で動く相手）
`engine/index.js` の `virtualTable` と `makeVirtualRunner` で、カードを使わず「ターンごとに何点で成功するか」の確率だけで動く相手と戦わせられます。noteの点数の進行どおりに動く相手との勝率を見るのに使います（今は画面には出していません）。
