# ラブカ対戦シミュレーター（match/）

ラブライブ！シリーズ オフィシャルカードゲームのデッキ同士を、実際のレシピで何試合も戦わせるシミュレーターです。
トップの `index.html`（CatChu!アグロシミュレーター）とは別のページです。

## 画面
- **対戦**：自分のデッキ vs 環境デッキ、または総当たり。タイプごとに保存した構築を選べます。
- **ひとり回し**：毎ターン何点出せるかを、デッキファイルに書いた点数の目安と比べます。
- **デッキとカード**：デッキの保存・呼び出し、デッキの決まりの確認、カード効果の組み込み状況。

## フォルダ
| フォルダ | 中身 |
|---|---|
| `engine/` | ルール本体（総合ルール ver.1.06）。`game.js` が1試合の進行、`ai.js` が標準のプレイ方針、`hearts.js` がハート判定 |
| `cards/` | カード効果。全デッキで共有する。`common.js` は効果の文章で登録（同じ文章のカードは全部これで動く）、グループごとのファイル（`liella.js` など）はカード番号で登録。どちらにも無いカードは数値だけで動く |
| `decks/` | 組み込みの環境デッキ。1デッキ1ファイルで、レシピ・回し方の目安（plan）・プレイ方針の上書き（strategy）を持つ |
| `store/` | 保存デッキの窓口。今は LocalStorage。DBに移すときは同じ形のクラスを作って差し替える |
| `data/` | カードデータ（`rabuka_cards.json` をそのまま使う）、前回取り込んだカード番号（`known-ids.json`）、ポイント制限 |
| `tools/` | 新弾レポート（`report.mjs`）、旧CatChu!シミュレーターとの比較（`compare-old.mjs`） |
| `test/` | 動作確認（`node match/test/smoke.mjs`） |

## カードデータの更新（新弾のとき）
1. 新しい `rabuka_cards.json` で `data/rabuka_cards.json` を置き換える（変換は不要）
2. `node match/tools/report.mjs` で、新カードと効果の対応状況を確認する
   - 既存カードと同じ文章の効果は自動で動く（「対応済み（文章）」）
   - 「未実装」の効果を `cards/` に書く。よく出る文章は `common.js` に文章で、そのカードだけの効果はグループのファイルに番号で
3. 確認が済んだら `node match/tools/report.mjs --update` で `known-ids.json` を更新する
4. `node match/test/smoke.mjs` で動作確認

画面の「デッキとカード」の下にも、同じ状況（新カード・対応状況）が出ます。

## デッキを足すとき
1. `decks/` にファイルを1つ作る（既存のファイルをまねる）
2. `decks/index.js` に1行足す
3. 足りないカード効果を `cards/` に書く

## 回し方の書き方（decks/*.js の strategy）
noteの回し方をデッキファイルに書き写すための項目です。全部書かなくても、標準のAIが動きます。

| 項目 | 中身 | 例 |
|---|---|---|
| `mulliganOpt.keep` | マリガンで残すカードの優先リスト（番号・コスト・枚数。`group` で「どちらか1枚」） | `[{ ids: ['PL!-bp6-019'], n: 1 }, { cost: 4, n: 1 }]` |
| `turnPlan` | ターンごとの目標の盤面（コストか `{ id, cost, area }`）と、置きたいライブの組み合わせ | `{ 4: { board: [[13, 13, 2]], lives: [[GN, MW]] } }` |
| `script` | そのターンに最初に出すカード（番号かコスト、エリア、バトンタッチ元）。出せなければ飛ばす | `{ 3: [{ play: { id: '…' }, area: 1 }] }` |
| `lock` | 指定のターンの間、バトンタッチしないメンバー | `[{ id: '…', area: 1, fromTurn: 3, toTurn: 4 }]` |
| `prefer.toWaiting` | 控え室に送っておきたいカード（踏み倒し・入れ替えの対象）。マリガンで残し、1Tから送る | `['PL!HS-bp6-007']` |
| `prefer.mill` | 山札を削りたいデッキ | `true` |
| `prefer.unit` / `prefer.bigLive` | 優先するユニット、2Tから1枚残す大きいライブの点数 | `{ unit: 'CatChu!', bigLive: 6 }` |
| `liveOpt.pace` | ライブの点数の進行（成功の回数ごとの目標点） | `[1, 4, 7]` |
| `liveOpt.onlyCombos` | 決まったターン・組み合わせでしか置かないライブ | MIRACLE WAVE を 4T は Guilty Night と |
| `liveOpt.fill` / `fillMaxCost` | ライブ置き場の空き枠に不要なメンバーを伏せて引き直す | `true` / `4` |
| `mainOpt.unitBonus` | ユニットの名前の種類をそろえる | `{ unit: 'CatChu!', w: 0.8 }` |

## AIの判断
- メインフェイズ：出せる組み合わせを全部試し、「手札のライブの成功の見込み × 点数」「ターンの目標の盤面との近さ」などで選ぶ。1枚出すごとに組み直す
- ライブ：対戦では、相手のデッキの点数の見込み（相手のひとり回しから作る）と比べ、「自分がライブに勝つ確率 − 相手がライブに勝つ確率」が一番高い置き方を選ぶ。どう置いても得にならなければ置かない。後攻は先攻が伏せた枚数も見る
- ひとり回しでは、点数の見込みと目標の進行で選ぶ

## 仮想の相手（noteの点数で動く相手）
`engine/index.js` の `virtualTable` と `makeVirtualRunner` で、カードを使わず「ターンごとに何点で成功するか」の確率だけで動く相手と戦わせられます。noteの点数の進行どおりに動く相手との勝率を見るのに使います（今は画面には出していません）。

## わかっていること（2026-11-13時点）
- CatChu! と僕光μ's は、ひとり回しの「うまくいったとき」の点数がnoteの目標とほぼ同じ
- タワーLiella!・恋アク・Edel Note は、4T以降の点数がnoteの目標より低い。そのためカード同士の総当たりでは CatChu! が強めに出る
- 詳しい数字はプロジェクトのメモ（環境7デッキ 総当たり）にまとめています
